# Workflows / Recipes

Workflows beschreiben wiederkehrende Kombinationen mehrerer Skills.

## Unterschied

```text
Skill
→ Wie erledige ich eine begrenzte Arbeitsdisziplin?

Workflow
→ Welche Skills werden für ein größeres Ziel in welcher Reihenfolge kombiniert?
```

Ein Workflow ist deshalb **kein neuer Mega-Skill**.

## Grundregeln

- lokale Projektanforderungen bleiben Source of Truth;
- nur die wirklich benötigten Skills aktivieren;
- zwischen Phasen klare Handoffs und Evidence verwenden;
- unabhängige Review-/Verification-Schritte nicht mit Erzeugung vermischen;
- Human Gates nicht durch Workflow-Automatik überspringen;
- fehlende Capabilities über die Fallbackregeln der beteiligten Skills behandeln;
- Workflows dürfen projektspezifisch verkürzt oder erweitert werden.

## Workflow-Handoff

Zwischen Phasen möglichst weitergeben:

- Ziel / Auftrag;
- relevanten Scope;
- gültige Projektregeln;
- erzeugte Artefakte;
- Evidence;
- offene Unsicherheiten;
- Gate-/Freigabestatus;
- erwarteten nächsten Output.

## Anpassung

Ein Workflow ist ein empfohlenes Muster, keine starre Prozesspflicht.

Kleine Aufgaben dürfen Schritte auslassen, wenn deren Schutzfunktion für die konkrete Aufgabe nicht benötigt wird.

Riskante oder komplexe Aufgaben dürfen zusätzliche Gates und Reviews ergänzen.

## Leitgedanke

> Skills bleiben klein. Workflows machen aus ihnen einen nachvollziehbaren Produktionsprozess.
