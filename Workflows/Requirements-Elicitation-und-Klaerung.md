# Workflow: Requirements Elicitation und Klärung

## Ziel

Aus einer vagen Initiative, vorhandenen Notizen oder widersprüchlichen Stakeholderaussagen die für die nächste Entscheidung relevanten Bedarfe, Constraints und Requirement Candidates gewinnen.

## Ablauf

```text
1. Elicitation-Ziel / nächste Entscheidung
→ 2. Sources / Stakeholder identifizieren
→ 3. vorhandene Evidence lesen
→ 4. requirements-elicitation
→ 5. Konflikte / Annahmen / Non-Goals klären
→ 6. requirements-specification für ausreichend bestätigte Candidates
→ 7. requirements-validation
→ 8. offene High-Impact-Fragen oder Handoff
```

## Skills

- `requirements-elicitation`
- `requirements-specification`
- `requirements-validation`

Optional:

- `requirements-baseline` bei Brownfield;
- `domain-modeling` bei fachlichen Begriffs-/Invariantenfragen;
- `research-plan` / `deep-research`, wenn externe Fakten erst erarbeitet werden müssen.

## Regeln

- bereits beantwortete Fragen nicht aus Ritual erneut stellen;
- Inferenz aus Notes/Systemen sichtbar markieren;
- keine numerische Clarity-Schwelle als Exit-Gate verwenden;
- technische Lösung nur als Constraint übernehmen, wenn sie autoritativ begründet ist;
- Außenkommunikation mit Stakeholdern bleibt separat autorisiert.

## Leitgedanke

> Elicitation ist eine gezielte Unsicherheitsreduktion, kein Fragebogenmarathon.
