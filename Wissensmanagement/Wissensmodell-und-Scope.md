# Wissensmodell und Scope

## Zweck

Eine Wissensbasis braucht ein bewusstes Modell dafür, welche Arten von Information sie enthält und welche davon als Wissen gelten.

## Ebenen

Ein robustes Grundmodell unterscheidet mindestens:

```text
Raw Source
→ unveränderte oder eindeutig referenzierte Quelle

Derived Knowledge Unit
→ daraus abgeleitete wiederverwendbare Erkenntnis

Synthesis
→ Verbindung mehrerer Wissenseinheiten zu einem höheren Bild

Navigation / Index
→ Zugangsschicht zu vorhandenem Wissen
```

Diese Ebenen dürfen physisch unterschiedlich umgesetzt werden. Die logische Trennung ist wichtiger als ein bestimmtes Ordnerschema.

## Raw Source

Rohquellen sollten nach Möglichkeit unverändert bleiben oder über eine stabile Referenz erreichbar sein.

Sie dienen als:

- Herkunftsnachweis;
- Re-Derivationsquelle;
- Gegenprüfung bei Konflikten;
- Schutz gegen stille Verfälschung abgeleiteter Notizen.

## Wissenseinheit

Eine Wissenseinheit soll eine wiederverwendbare Aussage, ein Konzept, eine Entscheidung, eine Beziehung oder einen anderen stabilen Erkenntnisgegenstand repräsentieren.

Sie besitzt möglichst:

- stabile Identität;
- verständlichen Titel oder Schlüssel;
- Inhalt beziehungsweise Claims;
- Provenance;
- Aktualitäts-/Gültigkeitsinformation, wenn relevant;
- Beziehungen zu anderem Wissen;
- Status oder Confidence, wenn die Aussage nicht gesichert ist.

## Synthese

Eine Synthese verbindet vorhandene Wissenseinheiten. Sie darf ihre Herkunft nicht unsichtbar machen.

Eine Synthese ist deshalb nicht automatisch Source of Truth. Sie ist eine abgeleitete Sicht auf Sources of Truth und andere Wissenseinheiten.

## Navigation

Indizes, Maps of Content, Dashboards, Views oder Suchindizes sind Zugangsschichten.

Sie dürfen automatisch erzeugt werden, wenn ihre Ableitung nachvollziehbar ist.

## Grenze zu Working State

Taskbezogener Arbeitszustand gehört zunächst zur Agentenarbeit.

Nur wenn eine Information über den aktuellen Task hinaus wiederverwendbar ist und die Qualitätskriterien der Wissensbasis erfüllt, soll sie bewusst in Persistent Knowledge überführt werden.

## Grenze zu Dokumentation

Dokumentation darf Wissen neu ordnen und erklären. Sie ist aber nicht automatisch die kanonische Wissenseinheit.

Ein Tutorial kann beispielsweise mehrere Wissenseinheiten verwenden, ohne dass sein Erzählfluss das Wissensmodell bestimmt.

## Leitgedanke

> Erst definieren, welche Wissensobjekte existieren sollen. Danach Ordner, Tags, Tabellen oder Graphen auswählen.
