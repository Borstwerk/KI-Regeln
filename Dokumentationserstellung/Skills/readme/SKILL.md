# Skill: readme

## Zweck

Ein README als verlässlichen Einstiegspunkt für ein Projekt erstellen oder überarbeiten.

## Vorgehen

1. Kläre, was das Projekt ist, für wen es gedacht ist und welches erste Ergebnis relevant ist.
2. Lies Repository-Struktur, vorhandene Befehle, Konfiguration und lokale Doku.
3. Schreibe zuerst einen kurzen konkreten Überblick.
4. Baue einen möglichst kurzen verifizierten Quick Start.
5. Ergänze Installation, Verwendung und Konfiguration nur so weit, wie sie für den Einstieg nötig sind.
6. Verlinke tiefe Reference, Architektur oder Contribution-Doku statt sie vollständig zu duplizieren.
7. Prüfe Befehle, Pfade und Links.
8. Entferne veraltete Badges, Befehle oder Aussagen.

## Typische Struktur

- Projektname und Zweck;
- Quick Start;
- Installation;
- Verwendung;
- Konfiguration;
- kurze Architektur-/Doku-Verweise;
- Entwicklung / Contributing;
- Lizenz.

Die Struktur ist kein Pflichtschema. Nicht benötigte Bereiche weglassen.

## Regeln

- In den ersten Absätzen muss erkennbar sein, was das Projekt tatsächlich macht.
- Kein Tech-Stack-Intro als Ersatz für den Projektzweck.
- Quick Start nur mit real funktionierendem Weg.
- README nicht zum vollständigen Handbuch aufblasen.
- Source of Truth bleibt Repository und Projektdokumentation.
